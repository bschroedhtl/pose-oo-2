4  Properties in Detail

From the outside, a property looks like a variable of the object: you read and assign it with the dot operator. On the inside, however, it consists of two small pieces of code, the accessors. get runs when the value is read, and set runs when a value is assigned. The set accessor receives the new value in a hidden parameter called value.

C# offers several ways to write a property, from a one-liner to a full block of code. This chapter shows them one after the other, and each time explains which problem the longer form solves. At the end, a table sums up which form to use when.

4.1 Automatic Properties

Most properties just store a value and hand it back. For them, the shortest form is enough, the automatic property (auto property). You only write the data type, the name, and which accessors exist:

public string FirstName { get; set; }

Using the property looks like using a variable:

Pupil pupil = new Pupil();
pupil.FirstName = "Max";

The value has to be stored somewhere. For an auto property, the compiler secretly creates a private field for it, the backing field, and fills in the accessor code. So the one-liner above behaves like this longer code:

private string _firstName; // created by the compiler, invisible to you

public string FirstName
{
    get { return _firstName; }
    set { _firstName = value; }
}

This is why a property is often called a public wrapper around a field: the field stores the value, and the property controls how it is read and written. Not every field needs a property, though. Data that is only used inside the class stays a plain private field.

4.1.1 Restricting Access

Often other classes may read a value but not change it. A pupil’s first name, for example, is set in the constructor and should not be overwritten from anywhere else in the program. To achieve this, make only the set accessor private:

public string FirstName { get; private set; }

Now every class can read pupil.FirstName, but only code inside Pupil can assign it. An access modifier on an accessor can only restrict access further, never widen it.

If a value never changes at all once the object exists, leave out set completely. Such a get-only property can only be assigned in the constructor:

public DateOnly DateOfBirth { get; }

4.2 When an Auto Property Is Not Enough

An auto property stores every value it gets, without looking at it. As soon as the property has to do something when a value is assigned, the set accessor needs a body of its own. There are three typical reasons:

  • Validation: reject values that make no sense. Pupil.ZipCode must stay between 1000 and 9999.
  • Transformation: store the value in a cleaned-up form. A name typed as " Max " should be stored as "Max".
  • Reacting to a change: do something extra whenever the value changes, e.g. write a message to a log.

Since C# 14 (.NET 10), the keyword field makes this easy. Inside an accessor, field stands for the hidden backing field that the compiler creates. So you write a body only for the accessor that needs special code, and the other one stays automatic (get;).

Validation: ZipCode accepts only four-digit ZIP codes.

public int? ZipCode
{
    get;
    set
    {
        if (value is >= 1000 and <= 9999)
        {
            field = value;
        }
    }
}

pupil.ZipCode = 4060; runs the set accessor with value = 4060, which passes the check, so field = value; stores it. pupil.ZipCode = 42; runs the set accessor too, but the check fails, so the old value stays.

Transformation: FirstName removes the spaces around a name before storing it. With a single expression, the short => form works (see Expression Syntax), and the setter can still be private:

public string FirstName
{
    get;
    private set => field = value.Trim();
}

Reacting to a change: LastName writes a message every time it changes, e.g. after a marriage:

public string LastName
{
    get;
    set
    {
        Console.WriteLine($"Changing last name from {field} to {value}");
        field = value;
    }
}

Note that the setter also runs when the constructor assigns LastName = lastName;. The first message is therefore “Changing last name from to Muster”, with an empty old value.

With field, you can start every property as a simple auto property { get; set; }. If you later notice that some values must be rejected or cleaned up, you give the set accessor a body. You don’t need to add a field or rewrite get, and the code that uses the property doesn’t change at all.

4.3 Explicit Backing Fields

Before C# 14, the field keyword didn’t exist. To give an accessor a body, you had to declare the backing field yourself and write both accessors. This is called a fully written-out property. You will see it in almost all existing C# code, so you need to be able to read it:

private int? _zipCode;

public int? ZipCode
{
    get
    {
        return this._zipCode;
    }
    set
    {
        if (value is >= 1000 and <= 9999)
        {
            this._zipCode = value;
        }
    }
}

It does exactly the same as the ZipCode with field above. A fully written-out property consists of these parts:

  • A private backing field that holds the value. By convention its name starts with an underscore and a lowercase letter (_zipCode).
  • The property itself, named like the field but starting with an uppercase letter (ZipCode). It usually has the same data type as the field.
  • The get accessor, which returns the field’s value.
  • The set accessor, which receives the new value in value and writes it to the field, often after a check.
NoteTwo correct ways

A property with an explicit backing field and a property with field do the same thing. When a class diagram lists the backing field (e.g. -int? _zipCode), write it out as shown in the diagram. Otherwise field is usually the shorter and safer choice: the compiler’s hidden field has no name, so no other code in the class can write to it and bypass the check.

4.4 Expression Syntax

If an accessor does nothing but a single expression, you can shorten it with => (expression syntax). You have already seen it in the FirstName setter above. It works for explicit backing fields as well:

private string _firstName;
public string FirstName
{
    get => this._firstName;
    set => this._firstName = value;
}

Expression syntax is only a shorter way of writing an accessor: get => this._firstName; means exactly the same as get { return this._firstName; }. As soon as an accessor needs more than one expression, like the if in ZipCode, you need the long form with braces.

4.5 Computed Properties

Some values don’t need to be stored at all, because they follow from other data. A computed property has only a get accessor and no backing field. Its value is calculated again every time someone reads it. That’s why it cannot have a set accessor: there is nowhere to store a value.

A pupil’s full name is a good example. It follows from first and last name, so storing it separately would only risk that the three values contradict each other. Expression syntax makes this a one-liner:

public string FullName => $"{FirstName} {LastName}";
ImportantThree different concepts

Don’t confuse these forms. An auto property ({ get; set; }) stores a value in a hidden field. Expression syntax (=>) is just a shorter way to write an accessor. A computed property stores nothing and computes its value on every read, and it can be written in either the long or the short form. public string FullName => ...; (computed, no set) is something completely different from public string FullName { get; set; } (stored).

A pupil’s age is computed too, because it changes over time, even if nothing in the object changes. It depends on the date of birth and today’s date:

/// <summary>
/// How many whole years lie between the date of birth and today
/// </summary>
public int Age
{
    get
    {
        int years = DateTime.Now.Year - DateOfBirth.Year;
        DateTime fullYearsDate = DateOfBirth.AddYears(years);
        if (fullYearsDate > DateTime.Now)
        {
            // This year's birthday hasn't happened yet
            years--;
        }
        return years;
    }
}

4.5.1 Complexity of Computed Properties

Whoever uses a property expects it to behave like a variable: reading it should be fast and should not change anything. A computed property must live up to that expectation. So keep it simple:

  • Fast: no expensive work, such as big loops or creating many objects. Someone might read the property a thousand times in a loop without suspecting that each read is expensive.
  • Short: a few lines at most, ideally just one.
  • No complex business logic, and no side effects. Reading a value must not change the object.
  • Methods called from the property count too: a one-line property that calls an expensive method is still expensive.

If you need more logic than that, write a method instead. A method call tells the reader “work is being done here”, and its result can be stored in a variable if it’s needed more than once.

4.6 Handling Invalid Values

What should a setter do when value fails the check? There are three options, each with an advantage and a drawback:

  1. Don’t set it at all: the object never gets an incorrect value, but the caller doesn’t learn that something went wrong.
  2. Throw an exception: the object never gets an incorrect value and the caller is notified, but the program stops unless the caller handles the exception. You will learn about exceptions later in the year.
  3. Set a meaningful default value instead: the object never gets an incorrect value and the program keeps working, but the caller gets no feedback about the invalid value.

Which option fits best is up to the author of the class and depends on the specific value and on what the program is for. Pupil.ZipCode uses option 1: an invalid ZIP code is simply ignored, as the exercise requires.

TipUse the properties inside the class, too

The class itself should use its properties as well, instead of accessing a backing field directly, even if that means working with a private setter. Otherwise a constructor could write _zipCode = 42; and bypass the check in the setter. When all code goes through the property, the checks always run and are written in one place only. With field this happens automatically, because there is no named backing field to write to.
