1  From Structured to Object-Oriented

In the first year you wrote structured (procedural) programs:

  • Methods do the work: each one fulfills a single task and is steered by its parameters.
  • Data is kept “on the side”: in variables, arrays (many values of the same type) and records (values of different types that belong together).

This works well for small programs. In larger ones, data and the methods working on it drift apart, and it gets hard to see who is allowed to change what.

Object-oriented programming (OO) puts data and logic back together: an object holds its data and the methods that work on that data. Each object is responsible for one part of the overall task.

1.1 Goals of OO

  • Reusability: an object is a self-contained building block that can be used in many places.
    • Single Responsibility Principle: a class should have exactly one responsibility.
  • Encapsulation: how an object works is hidden inside. Other code only uses its public interface (a “contract”), so the inside can change without breaking the outside.
  • Testability and extensibility: a defined interface is easy to test, and an object can later get new capabilities.

1.2 What Is an Object?

An object has two sides that only make sense together:

  • State: its data. A pupil has a first name, last name, date of birth and ZIP code.
  • Behavior: its methods. A pupil can tell whether it is of full age, whether it is older than another pupil, or whether it lives nearby.
ImportantObject = state + behavior

Behavior uses the state and may change it, and the state influences the result of the behavior. Only together do they make up an object.

The blueprint for objects is a class. It is similar to a record, but contains not only data, it also contains behavior.

1.3 Finding Classes

To design an object-oriented program, read the task description and look for the important nouns: they are candidates for classes. Then decide which data each class needs (state) and what it must be able to do (behavior).

Example: for a school administration, Pupil is an obvious class:

State (fields) Behavior (methods)
FirstName, LastName IsOfFullAge
DateOfBirth IsOlderThan
ZipCode, City LivesNearby
