5  Static vs. Instance

So far, everything in a class belonged to the individual objects: every pupil has its own first name, its own date of birth, its own ZIP code. Members like these are called instance members, and they remain the normal case.

Sometimes, however, a value belongs to the class as a whole rather than to one object. The 01-Pupils exercise has such a case: every pupil gets a unique, ever-increasing Id. To hand out the next id, somebody has to remember which id comes next. That counter can’t be stored in each pupil, because every pupil would have its own copy and they would all start at the same number. It must exist once for the whole class. Members like that are marked with the keyword static.

5.1 Fields

A static field exists exactly once, no matter how many objects there are, and all instances share it. When one pupil changes it, all other pupils see the new value:

public class Pupil
{
    private static int _nextId = 1;

    public int Id { get; }

    public Pupil(string firstName, string lastName, DateOnly dateOfBirth)
    {
        Id = _nextId;
        _nextId++;
        // ... remaining initialization
    }
}

Every time a new Pupil is created, the constructor copies the shared _nextId into the pupil’s own Id, then increases the counter for the next pupil. The first pupil gets id 1, the second id 2, and so on. That’s why _nextId must be static, while Id is a normal instance property: every pupil has its own id, but they all share one counter.

WarningSide effects

Use static fields very carefully. A change made through one object silently affects all the others. This is called a side effect, and it’s a common source of bugs that are hard to find. It can also make tests depend on each other, because the shared value survives from one test to the next.

5.2 Methods

Methods can be static, too. A static method belongs to the class, not to an object, so it runs without any instance. That’s why you call it via the class name: Console.WriteLine(...) and Math.Max(...) are static methods, and so were all the methods you wrote in the first year.

This has a few consequences:

  • A static method cannot use instance fields or properties, and cannot use this: there is no “current object” whose data it could access. It can use static fields.
  • Its only way to work with objects is to receive them as parameters.
  • Apart from that it’s a normal method: it can be overloaded, and access modifiers like public and private apply as usual.

Although static methods belong to the class, good static methods are the opposite of side-effect-prone code. They work only with their parameters and return a result, without keeping any data between calls. We call such methods stateless. They are easy to understand and easy to test, which is why they were all you needed in the first year. If a method doesn’t use any instance data, the IDE often suggests making it static.

5.3 Static Class

If a class contains only static members, you can declare the class itself as static class. This is typical for a collection of helper methods that don’t need any state. The best-known example is System.Math: Math.Sqrt, Math.Round and Math.Max are all static, and a “math object” would make no sense.

Note

You cannot create an instance of a static class. new Math() does not compile.

5.4 const, readonly and static Compared

Three keywords change how a field behaves, and they are easy to mix up: const, readonly and static. They answer two different questions:

  • How many copies exist? One per object (instance field), or one for the whole class (static, and every const).
  • When can the value change? Never, because it is fixed in the code (const); once, in the constructor (readonly); or any time (neither).

This HorseRace class uses all of them:

public class HorseRace
{
    public const int MaxSteps = 20;
    public static readonly DateTime StartTime = DateTime.Now;
    private static int _raceCount;
    private readonly Horse[] _horses;

    public HorseRace(Horse[] horses)
    {
        _horses = horses;
        _raceCount++;
    }
}

const: a constant, fixed when you write the code. MaxSteps is 20 in every race and in every run of the program. The compiler writes the value directly into every place where MaxSteps is used, so it must be known at compile time: a number, a bool, a char or a string literal. DateTime.Now or new Horse[5] are not possible. A constant belongs to the class, not to an object, so you use it via the class name: HorseRace.MaxSteps. It is automatically static, and writing static const is even a compile error.

readonly: set once, then fixed. _horses gets its value in the constructor, and after that nobody can assign a different array to it, not even the class itself (_horses = ...; in a method is a compile error). Unlike a constant, the value is only known at runtime: each race gets the horses that are passed to its constructor. So every object has its own readonly value.

static: one copy for the whole class. _raceCount exists once and counts all races ever created. Without readonly, it can change at any time, with the side effects described above.

static readonly: one copy, set once at runtime. StartTime exists once for the whole class and never changes, but its value is only known when the program runs, so it can’t be a const. Use static readonly for constants that the compiler can’t compute: a DateTime, an array, an object.

Keyword Copies Value is set … Can change later? Example
(none) one per object anywhere in the class yes private int _position;
readonly one per object at the declaration or in the constructor no private readonly Horse[] _horses;
static one for the class anywhere in the class yes private static int _raceCount;
static readonly one for the class at the declaration no public static readonly DateTime StartTime
const one for the class in the code, at compile time no public const int MaxSteps = 20;

To choose, ask the two questions from above:

  • Is the value the same for every object and known when you write the code? Use const.
  • Is it the same for every object, but only known at runtime? Use static readonly.
  • Does each object get its own value that never changes after the constructor? Use readonly.
  • Does the value change while the program runs? Leave readonly out, and add static only if all objects must share it.
Warningreadonly protects the reference, not the object

For an array or another object, readonly only means that the field always refers to the same array. The contents can still change: _horses[0] = new Horse("Lara"); compiles and replaces the first horse, and sorting the array rearranges its elements. readonly prevents only _horses = new Horse[3];.

For properties, the same idea is called a get-only property (public int Age { get; }, see Properties in Detail): like a readonly field, it can only be assigned in the constructor.
